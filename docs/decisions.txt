DECISIONS - options weighed and why

D1 Whose side?  Options: creator agent, brand agent, neutral broker.
Chosen: neutral broker with one published rule. Brand-side needs creator data we lack. Creator-only leaves brands no
reason to trust it. Cost: it cannot advocate for a creator who sets a low floor, so we add price guidance.

D2 Where does the flow start?  Options: brand brief first, creator first.
Chosen: creator first, with a company side too. Finding brands for small creators is the service nobody offers them.

D3 Two negotiation engines or one?
Chosen: one engine, two views. Two engines could disagree, and neither side could trust the result.

D4 How is price set?  Options: LLM haggling, multi-round concessions, sealed limits with a fixed rule.
Chosen: sealed limits with the midpoint, the Nash bargaining solution. It is deterministic and easy to explain.
Limit: nobody can guarantee honest limits (Myerson-Satterthwaite). We say so.

D5 Does a name match verify a sender?
Tested: no. Run 1 found 4 same-name false matches, so a name match is only weak evidence.

D6 How do we find brands?
Tested: plain Company Search found known brands on 1 of 4 queries. Job Search finds brands already hiring for
influencer roles but skews large. With a size filter, Company Search does return small brands. We use both.

D7 Where does creator data come from?
Tested: Web Fetch reads public Instagram pages; a direct request got nothing. Views are absent, so engagement uses likes
and comments. Social search is too flaky for discovery, so creators register themselves.

D8 Who decides, the LLM or code?
Chosen: code. The same input must give the same answer. The LLM reads messy text and drafts messages, with a fallback.

D9 Stack: FastAPI and SQLite in one process. Fast to build and easy to run. A real launch would need a proper queue.

D10 Tiebreaks: published chains, not manual choice or hidden scores.
Creator choosing a company: pay (within 2% is a tie) -> safer payment -> fewer restrictions -> fit -> earliest -> fair lot.
Company choosing a creator: fit -> evidence -> price -> engagement -> fewer deals so far -> smaller creator -> fair lot.
Merit comes first; then the choice spreads income to smaller creators, which is the product's purpose. Fair lot is a
hash, not database order, so nobody wins an exact tie by signing up first.
Equal-surplus options: fewer restrictions on the creator. Race for exclusivity: first to sign, reserved atomically.

D11 Niches are free text, with no fixed list. Vocabulary is learned from Crustdata results for the phrase itself.
D12 Rate limits: pages answer from the cache and score the rest in the background, so nobody waits on a limit.
app/prewarm.py pre-loads known niches (data/known_niches.json). Rotating teammates' keys speeds it up.
D13 Broad niches: "vlogging" search returns media peers, not buyers, so those are filtered out. If nothing remains, the
creator sees brands hiring for creator marketing across niches, labelled "fit not proven".
D14 Brand discovery query. Compared 4 phrasings live on 3 niches. "consumer brand selling X products" found real consumer
brands; "X brand" matched names containing the word brand. A niche match now needs the company's own text.
D15 Showing the work. Deal steps make real Crustdata lookups and list each one (source, live or cached, time). An optional
pace setting slows steps for viewers, and the deal page says so while it is on. GSAP motion follows real events only.
D16 Auto Deal thresholds: likelihood >= 55, confidence >= 40, verified or partly verified, at most 10. Stricter than the 45
needed just to be shown, because it acts without asking. It only applies; the brand still chooses and signs.
